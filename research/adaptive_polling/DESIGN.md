## 1. 问题形式化

### 1.1 到达过程

A 端产生 READY 事件（归档包就绪）时刻序列 `a_1 < a_2 < ... < a_N`（秒，A 时钟）。
到达过程**与 B 的查询行为独立**（外生），这是“配对比较”成立的前提：同一条到达轨迹
可以原样喂给所有策略。仿真中考虑的到达族见 §4。

### 1.2 观测模型（与 PATCH-01 §9 一致）

B 在时刻 `q` 发起一次 READY 查询（一次 SSH 请求）：

* **成功**：返回快照时刻 `s=q` 以及所有 `a_i <= s` 且尚未被发现的批次的**精确 `ready_at`**。
  因此区间 `(s_prev, s]` 的事件计数和每个事件的精确时刻都已知；
  “成功但 0 个 READY” 是一个**有效的暴露量观测**（计数 0，暴露 `s - s_prev`）。
* **失败**（超时/断网/认证失败）：**不揭示任何到达信息**，不得当成“0 个包”，
  不调用 `PollPolicy.observe`。失败后的重试间隔由独立的 `RetryPolicy` 决定
  （与 `adaptive-archive-sync/src/aas/b/scheduling/policy.py::RetryPolicy` 相同：初值 10s、翻倍、上限 300s；
  仿真中关闭 jitter 以保证可复现）。
* 失败之后的下一次成功查询的暴露区间是 `(上一次成功快照, 本次快照]`，
  它**包含**故障期，这是正确的：因为 `ready_at` 是精确的，故障期内到达的包会在这次成功查询中
  被完整列出，所以对率估计没有偏差；失败本身从不产生样本。
* 唯一的右删失是“当前尚未完成的间隔”：最后已知到达 `a_last`、最后成功快照 `s`，
  只知道 `X_next > s - a_last`。策略只在**条件化**时使用它（`S(e+u)/S(e)`），
  从不把它当作完整间隔样本，也不重复累计。

### 1.3 发现延迟与代价

* 首次发现时刻 `d_i = min{ 成功查询的完成时刻 c_j : 其快照 s_j >= a_i }`，
  发现延迟 `D_i = d_i - a_i`（仿真中查询耗时 `scan_duration=2s`，所以 `D_i` 至少 2s）。
* 报告每个 run 的 `D` 的 P50 / P95 / P99 / 均值 / 最大值。
* SSH 查询次数 `N_q` = 成功非空 + 成功空 + 失败（含 PATCH-01 §2.3 的“一次有界立即复查”）。
  `polls/hour = N_q / H`。
* 组合代价（每小时）：

  `J_c = ( c · N_q + Σ_i D_i ) / H`，其中 `c = c_q / c_d`（单位：包·秒 / 次查询）。

  报告 `c ∈ {3, 10, 30, 100, 300}`。对平稳 Poisson（速率 λ 包/小时）固定周期 `T`：
  `J = 3600c/T + λT/2`，最优 `T* = sqrt(7200c/λ)`；λ=6/h 时 c=3,10,30,100,300 分别对应
  T* ≈ 60, 110, 190, 346, 600s，正好被 `T ∈ {30,60,120,300,600}` 覆盖。
* 其他指标：积压峰值（A 上已 READY 但 B 尚未发现的批次数的最大值）、
  传输队列（2 个 worker、FIFO、每包服务时间预生成）下的端到端（READY→传输完成）P95、
  失败查询数、立即复查次数。
* 终端处理：轨迹只在 `[0, H]` 内生成到达；仿真在 `H` 之后继续运行，直到 `[0,H]` 内所有包
  都被发现为止，期间的查询**照样计费**（防止慢策略因截尾获得虚假的低延迟）。

### 1.4 理论负控制

平稳齐次 Poisson、查询成本恒定时，由 Jensen 不等式，相同平均查询率下固定周期不劣于任何仅依赖历史的
自适应周期（survey §8.1）。所以在 `poisson` 工作负载上，任何自适应策略都**不应**显著优于调好的固定周期；
如果出现大幅“胜出”，优先怀疑仿真器泄漏或记账错误。

## 2. 接口（对齐 PATCH-01 §2.2）

所有策略实现：

```python
policy_name: str
validate_config() -> None
observe(event) -> None              # 只在成功扫描后调用
next_delay_seconds(context) -> float  # 纯函数：不修改状态
export_state() -> dict              # JSON 可序列化，含 schema_version / policy_name / config
import_state(state: dict) -> None   # 校验 schema / 策略名 / 配置一致
```

`event` 是 `ResearchDiscoveryObservation`：在生产 `DiscoveryObservation` 的四个字段
（`observed_ready_events, newly_enqueued_batches, queried_pages, completed_at_monotonic`）
之外，增加 PATCH-01 §2.2 注释里允许的可选字段：`snapshot_at`（A 时钟的快照边界）和
`ready_at`（本次新发现批次的 A 端 READY 时刻）。如果传入的是不带这些字段的生产
`DiscoveryObservation`，策略退化为仅用计数 + B 单调时钟暴露量（不更新间隔统计）。

统一安全约束：所有策略的输出钳制在 `[min_poll_s, max_poll_s]` = **[30, 600] s**，
这与固定基线的周期范围 `{30..600}` 相同（自适应策略不能获得固定基线没有的更长/更短间隔）；
`max_poll_s` 同时就是发现延迟 SLO 上限（正常网络下发现延迟 ≤ 600s + 扫描耗时）。

策略**只**决定下一次 READY 查询的时间；不接触 READY/ACK/VerifyGate/删除语义。
网络失败与重试由仿真器中的 `RetryPolicy` 负责，策略看不到失败。

## 3. 候选策略

| ID | 名称 | 估计器 | 决策规则 | 旋钮（5 档，训练种子上选择） |
|---|---|---|---|---|
| F | `fixed_interval` | 无 | `T` 常数 | `T ∈ {30,60,120,300,600}` |
| A | `gamma_poisson`（设计方案 §8.1 原文） | 双时间尺度（半衰期 1h / 12h）带遗忘的 Gamma–Poisson 伪计数/暴露；事件按精确 `ready_at` 逐个衰减 | `T = clamp(poll_factor·3600/r̂)`，再按 SLO 截断 | `poll_factor ∈ {0.02,0.05,0.1,0.2,0.5}` |
| A' | `gamma_poisson_sqrt` | 同 A | 代价最优平方根律 `T = clamp(sqrt(7200c'/r̂))` | `c' ∈ {3,10,30,100,300}` |
| B | `renewal_window` | 到达**间隔**的 EWMA 均值/方差（正确的更新过程估计；率 = 1/E[X]，不是 EWMA(1/X)） | CV ≤ 0.35 且样本足够：睡到预测窗口 `[m−2.5σ, m+2.5σ]` 起点，窗内每 `max(30, min(κm, σ))` 探测；否则/窗口错过：`T = κ·max(m, e)`（`e` 为当前间隔已存活的年龄，删失下界） | `κ ∈ {0.05,0.1,0.2,0.4,0.8}` |
| C | `hazard_renewal`（本研究的改进候选） | 最近 64 个完成间隔的**时间加权、核平滑经验生存函数**（无完成间隔被删失 → 即 Kaplan–Meier），与 Gamma–Poisson 指数尾部混合；当前间隔用 `S(e+u)/S(e)` 条件化（正确使用右删失）；CUSUM（k=2, h=5）检测速率变点后把慢速率估计重置为快估计 | 用更新方程在 10s 网格上算期望到达强度 `m(u)`（含一个间隔内多个到达），期望累计等待 `C(Δ)=∫(Δ−u)m(u)du`，取平均代价相对值 `argmin_Δ C(Δ) − g·Δ`，`g` = 实现的长期代价率（排除含失败的区间，收缩到 Poisson 最优 `sqrt(2c'λ)`）。初稿用的是更新-报酬比 `argmin (C(Δ)+c')/Δ`，开发期冒烟调试发现它在近周期峰值附近“平坦”导致错过到达，遂改为前者；比值版本作为消融保留 | `c' ∈ {3,10,30,100,300}` |
| L | `long_poll`（参考上界，非 PollPolicy） | — | 一次阻塞请求，有新 READY 或超时（300s）即返回，立即重发；每个请求计 1 次查询，失败同口径记账 | `timeout ∈ {300}` |

说明：
* C 在平稳 Poisson 下退化为 `sqrt(2c'/λ)`，即与 A' 相同（负控制自洽）；在近周期到达下会“睡过空档、在预测峰附近查询”。
* B 与 C 都只用**已成功观测**的信息；`next_delay_seconds` 为纯函数（单元测试检查）。

## 4. 工作负载（每个种子独立生成，H = 96 小时）

| 名称 | 定义 | 平均率 |
|---|---|---|
| `poisson` | 齐次 Poisson λ=6/h（负控制） | 6/h |
| `periodic` | 生成器定时出包：间隔 600s + N(0, 30²)（CV≈0.05），随机初相 | 6/h |
| `onoff` | 2 状态 MMPP：ON 30/h、OFF 0.5/h，平均 ON 1h、OFF 3h | ≈7.9/h |
| `drift` | 每 12h 速率阶跃，从 {1,3,10,30}/h 随机抽 | ≈11/h |
| `diurnal` | 非齐次 Poisson `λ(t)=6·exp(1.5cos(2π(t−φ)/24h))/I0(1.5)`，随机相位 | 6/h |
| `idle_burst` | 背景 0.2/h；每 12–30h 一次 30 分钟、60/h 的突发 | ≈1.5/h |
| `packer` | 原始文件按日周期 Poisson（均值 120 文件/h）到达，满 50 个文件或首文件等待 1200s 即封包，封包耗时 U(20,120)s 后 READY（近似规则 + 速率变化） | ≈2.5–3/h |

网络故障轨迹（与策略无关、每种子预生成、配对共享）：
* 断网区间：Poisson 到达，平均每 12h 一次，持续时间对数正态（中位数 5 分钟，σ=1），期间所有查询失败；
* 瞬时失败：以 1s 为粒度预生成的伯努利场（p=0.01），在该秒发起的查询失败；
* 失败查询耗时 10s 后被识别，随后交给 RetryPolicy。

传输模型：每包服务时间对数正态（中位数 60s，σ=0.8）预生成，2 个并行 worker，FIFO。

## 5. 实验协议

* 训练种子 `0..9`、测试种子 `1000..1019`（20 个）。每个策略族的唯一旋钮在**训练种子**上按
  每个 (workload, c) 选择 `mean J_c` 最小的档位，然后在测试种子上冻结评估（对应 survey 的 Fixed-Train-Oracle；
  对固定基线和自适应策略同等对待）。
* 配对：同一 (workload, seed) 的到达轨迹、传输服务时间、故障轨迹对所有策略完全相同。
* 配对差异：`ΔJ_rel = (J_fixed_best − J_candidate) / J_fixed_best`（正 = 自适应更好），
  对 20 个测试种子做 bootstrap（10 000 次重采样）给 95% CI。
* 匹配查询预算的比较：每个种子上用固定基线 5 个点在 log(polls/h)–log(延迟) 上插值，得到
  “相同查询率下固定周期的平均延迟”，与自适应点对比（Pareto 图）。
* 资源：微基准测量 `observe` / `next_delay_seconds` 的 P50/P99/最大耗时，以及 `export_state` 的 JSON 字节数。
* 冷启动敏感性：最佳候选在 `r0 ∈ {1.5, 6, 24}`（真实率的约 ×0.25…×4）下重跑。

## 6. 预注册的“优于固定轮询”判定标准（进入生产的必要条件）

候选策略 X 必须**同时**满足以下全部条件，才可以说“满足 PATCH-01 §16 的预先设定的优于固定轮询标准”：

* **G1 主收益**：对 `c ∈ {10, 30, 100}` 中**每一个** c，在 6 个非 Poisson 工作负载中**至少 4 个**上，
  相对“训练选出的最佳固定周期”的配对平均 `ΔJ_rel ≥ 5%`，且 95% bootstrap CI 下界 > 0。
* **G2 不伤害**：对 `c ∈ {10, 30, 100}`、所有 7 个工作负载，平均 `ΔJ_rel ≥ −2%`
  （即任何场景都不能比最佳固定周期差 2% 以上）。
* **G3 尾延迟**：对 `c ∈ {10, 30, 100}`、所有工作负载，X 的测试均值 P95 发现延迟不超过固定最佳的 1.10 倍，
  P99 不超过 1.15 倍，**或者**同时其查询数更少且 J 更好（尾延迟换查询需在报告中单列）。
  —— 为避免歧义，判定时采用严格版：P95 ≤ 1.10×、P99 ≤ 1.15×。
* **G4 负控制**：在 `poisson` 上，X 不得出现 `ΔJ_rel > 5%` 且 CI 排除 0 的“胜出”（出现即视为仿真疑似泄漏，判失败直至查明）。
* **G5 可靠性**：所有 run 中所有包都被发现；故障期间策略从未收到 observe；状态导出/导入后决策逐位一致。
* **G6 资源**：`observe` 和 `next_delay_seconds` 单次 P99 < 1ms，状态 JSON < 1MB。

**修订记录（实验后追加，未改动上面的 G1–G6 定义）**：首轮结果中 `gamma_poisson_sqrt` 在 `poisson`
上触发 G4（+7.7%，CI 排除 0）。按 G4 的规定先查原因：5 档网格 `{30,60,120,300,600}` 不含 Poisson 的
代价最优周期（c=30 时 T*≈190s），自适应策略只是“连续地”选到了更好的周期（网格离散化收益），不是泄漏。
因此追加一个**补充**强基线 `fixed_fine`（同一 FixedIntervalPolicy，18 档 30…600s，训练种子选档），
并用同一套 G1–G6 再判一次。预注册判定（5 档基线）与补充判定（18 档基线）在报告中并列给出。

此外，即使 G1–G6 全部通过，由于全部证据来自**合成**轨迹，结论最多是“可进入影子模式（shadow mode）
用真实 READY 日志做反事实回放”，而**不是**直接改变生产默认；生产默认保持 `fixed_interval`。
